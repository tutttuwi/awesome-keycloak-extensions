✓What it can doできること3

  • Listen to admin events about users, roles and groups (role assignments, composite roles, group membership) and publish them to OpenFGA as relationship tuples.ユーザー・ロール・グループに関するAdminイベント（ロールの付与、ロール同士の関係、グループ所属）を受け取り、OpenFGAに関係タプルとして送信
  • Lets apps and APIs use OpenFGA (ReBAC, Zanzibar-style) as the policy decision point while Keycloak stays the source of roles.ロールの管理はKeycloakのまま、アプリやAPIはOpenFGA（ReBAC、Zanzibar方式）をポリシー判定点として使える
  • Ships an editable authorization model, and discovers the store and model IDs automatically when they are not set.編集可能な認可モデルが付属。ストアIDとモデルIDは未設定なら自動で検出

✕What it cannot do / limitsできないこと・制約4

  • Only syncs the identity/role/group model events it handles — the README does not describe initial bulk sync of existing data.同期されるのは対応しているIdentity/ロール/グループのイベントだけ。既存データの初回一括同期についてはREADMEに記載がない
  • If the API URL is unset it falls back to http://openfga:8080, meant for demos only.API URLを設定しないと、デモ用の http://openfga:8080 が使われる
  • Not tested on the WildFly-based distribution.WildFly版ディストリビューションでは未検証
  • Inactive — no commits since July 2024.2024年7月以降コミットがなく、活動停止状態

Requirements前提条件

  • A running OpenFGA server; copy the JAR to providers, set the KC_SPI_EVENTS_LISTENER_OPENFGA_EVENTS_PUBLISHER_* variables and enable openfga-events-publisher per realm.稼働中のOpenFGAサーバー。JARを providers に置き、KC_SPI_EVENTS_LISTENER_OPENFGA_EVENTS_PUBLISHER_* を設定して、realmごとに openfga-events-publisher を有効化
