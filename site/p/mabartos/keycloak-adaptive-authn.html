✓What it can doできること5

  • Change authentication requirements in real time from a risk score — ask for more factors when a login looks suspicious, fewer when risk is low.リスクスコアに応じて認証要件をリアルタイムに変える。怪しいログインでは要素を増やし、低リスクなら減らす
  • Score risk before authentication: browser, operating system, client sensitivity and GeoIP location.認証前の評価：ブラウザ、OS、クライアントの機密度、GeoIPによる位置
  • Score risk once the user is known: known IPs and locations, unusual login times, failed-login patterns and privileged roles.ユーザー特定後の評価：既知のIP・位置、普段と違うログイン時刻、ログイン失敗のパターン、特権ロール
  • Evaluate continuously during the session (concurrent sessions across IPs, bursts of sensitive account changes).セッション中も継続評価（複数IPからの同時セッション、機密性の高いアカウント変更の集中）
  • Use AI engines (OpenAI, Anthropic Claude, Google Gemini, OpenRouter) for complex account-takeover analysis, with user data anonymised first.複雑なアカウント乗っ取り分析にAI（OpenAI、Anthropic Claude、Google Gemini、OpenRouter）を使える。ユーザーデータは送信前に匿名化

✕What it cannot do / limitsできないこと・制約5

  • AI evaluation depends on external services (API keys, data leaves your network, even if anonymised).AIでの評価は外部サービスに依存する（APIキーが必要で、匿名化されるとはいえデータは外部に出る）
  • Supports only Keycloak 26.6.x, 26.7.x and nightly (26.5.x testing ended).対応はKeycloak 26.6.x・26.7.x・nightlyのみ（26.5.xはテスト終了）
  • Needs Keycloak's declarative-ui feature enabled.Keycloakの declarative-ui 機能を有効にする必要がある
  • Authentication policies were moved to a separate repository (mabartos/keycloak-authn-policies).認証ポリシー機能は別リポジトリ（mabartos/keycloak-authn-policies）に移った
  • The IBM Granite engine is deprecated.IBM Graniteエンジンは非推奨

Requirements前提条件

  • Add the core JAR (plus any extension JARs) to providers; follow the Start Guide for configuration.コアJAR（と必要な拡張JAR）を providers に追加。設定はStart Guideに従う
  • An API key for the chosen AI engine if AI evaluators are used.AI評価器を使う場合は、選んだAIエンジンのAPIキー
