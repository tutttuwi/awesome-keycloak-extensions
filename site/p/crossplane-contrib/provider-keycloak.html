✓What it can doできること5

  • Configure Keycloak declaratively from a Crossplane control plane — CRDs for realms, clients, roles, protocol mappers and more, reconciled against drift.Crossplaneのコントロールプレーンから、Keycloakを宣言的に設定できる。realm・クライアント・ロール・プロトコルマッパーなどのCRDがあり、ずれは自動で修正される
  • Cover the same resources as the Keycloak Terraform provider (generated with Upjet).KeycloakのTerraformプロバイダーと同じリソースを扱える（Upjetで生成）
  • Connect to several Keycloak instances with one ProviderConfig each; credentials come from Kubernetes secrets.ProviderConfigを分ければ複数のKeycloakに接続できる。認証情報はKubernetesのSecretから取得
  • Tune concurrency (--max-concurrent-reconciles, --keycloak-client-pool-size).並列度を調整できる（--max-concurrent-reconciles、--keycloak-client-pool-size）
  • Import Keycloak's built-in objects (default clients, roles) through a companion Crossplane function.付属のCrossplane Functionで、Keycloakの組み込みオブジェクト（デフォルトのクライアントやロール）を取り込める

✕What it cannot do / limitsできないこと・制約3

  • Not a Keycloak extension — needs a Kubernetes cluster with Crossplane.Keycloak拡張ではなく、Crossplaneを入れたKubernetesクラスタが必要
  • Does not install Keycloak; it only configures an existing instance.Keycloak自体はインストールしない。既存インスタンスを設定するだけ
  • Features and limits follow the underlying Terraform provider it is generated from.機能と制約は、生成元のTerraformプロバイダーに準じる

Requirements前提条件

  • Crossplane installed in the cluster and a ProviderConfig with the Keycloak URL and admin credentials.クラスタにCrossplaneを導入し、KeycloakのURLと管理者認証情報を持つ ProviderConfig を用意
