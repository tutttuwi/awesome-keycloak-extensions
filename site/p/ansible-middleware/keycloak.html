✓What it can doできること4

  • Install Keycloak (Quarkus-based, 19+) on hosts with an Ansible role, including clustered setups; the legacy role covers older WildFly-based versions and RH-SSO.Ansibleのロールで、Keycloak（Quarkus版、19以降）をホストにインストールできる（クラスタ構成にも対応）。旧ロールでWildFly版やRH-SSOにも対応
  • Install offline from the controller node or from alternate sources (Nexus, Artifactory, proxy).コントローラノードからのオフラインインストールや、社内リポジトリ（Nexus、Artifactory、プロキシ）からの取得が可能
  • Configure realms, user federation, clients, client roles and users through a role.ロールで、realm・ユーザーフェデレーション・クライアント・クライアントロール・ユーザーを設定
  • Manage a running Keycloak with modules (e.g. client scopes with protocol mappers, authentication flows); migrate from community.general modules by renaming the prefix.稼働中のKeycloakをモジュールで管理（プロトコルマッパー付きクライアントスコープ、認証フローなど）。community.general からはプレフィックス変更で移行可能

✕What it cannot do / limitsできないこと・制約3

  • Not a Keycloak extension — an Ansible collection run from a controller.Keycloak拡張ではなく、コントローラから実行するAnsibleコレクション
  • Red Hat customers should use the certified redhat.rhbk / redhat.sso collections instead.Red Hatの顧客は、認定版の redhat.rhbk/redhat.sso コレクションを使うべきとされている
  • For clusters, all hosts must be targeted by the same playbook run.クラスタ構成では、全ホストを同じplaybook実行の対象にする必要がある

Requirements前提条件

  • Ansible 2.16+ and the Python packages netaddr and lxml on the controller.Ansible 2.16以上と、コントローラ上のPythonパッケージ netaddr・lxml
