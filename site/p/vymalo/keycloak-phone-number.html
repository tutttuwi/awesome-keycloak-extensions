✓What it can doできること4

  • Log in with a phone number and an SMS one-time code (TAN), instead of or in addition to a password.電話番号とSMSのワンタイムコード（TAN）でログインできる。パスワードの代わりにも、追加要素としても使える
  • Create the user after phone verification if none exists, then let them update their profile.該当ユーザーがいなければ電話番号の確認後に作成し、続けてプロフィールを更新させられる
  • Send SMS through a REST API (basic auth or OAuth2 client credentials) or by publishing events to AMQP, RabbitMQ, Kafka or SNS/SQS.SMSの送信は、REST API（Basic認証またはOAuth2クライアントクレデンシャル）か、AMQP・RabbitMQ・Kafka・SNS/SQSへのイベント送信で行える
  • Restrict accepted country codes with a regex.受け付ける国番号を正規表現で制限できる

✕What it cannot do / limitsできないこと・制約3

  • Does not send SMS itself — you need an SMS API or a consumer that delivers the queued messages.SMSを自分では送らない。SMS APIか、キューに積まれたメッセージを配信する仕組みが別途必要
  • For queue-based providers, the TAN is validated locally with a fixed 5-minute, one-time TTL.キュー経由の方式では、TANはKeycloak側で検証され、有効期限は5分固定・1回限り
  • Configured only through environment variables.設定は環境変数のみ

Requirements前提条件

  • The login JAR plus the gateway JAR for your chosen SMS provider in Keycloak's providers directory.ログイン用JARと、選んだSMS送信方式のゲートウェイJARをprovidersに置く
