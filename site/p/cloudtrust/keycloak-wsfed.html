✓What it can doできること4

  • Add WS-Federation (passive requestor profile) as a client protocol, with Keycloak acting as IdP/STS — e.g. for SharePoint.WS-Federation（パッシブリクエスタ）をクライアントプロトコルとして追加し、KeycloakをIdP/STSとして使える（SharePointなど）
  • Broker to other WS-Fed IdPs, with Keycloak acting as an identity broker.Keycloakをブローカーとして、他のWS-Fed IdPと連携できる
  • Issue SAML 2.0 or SAML 1.1 tokens, optionally encrypted, with front- or back-channel logout.SAML 2.0/1.1のトークンを発行し（暗号化も可）、フロントチャネル/バックチャネルのログアウトに対応
  • Use SAML mappers plus a JavaScript mapper, and publish WS-Fed metadata.SAMLのマッパーに加え、JavaScriptマッパーも使える。WS-Fedのメタデータも公開

✕What it cannot do / limitsできないこと・制約3

  • Only passive (web) requestors — active requestors and the optional attribute and pseudonym services are not supported.対応はパッシブ（Web）リクエスタのみ。アクティブリクエスタや、任意機能の属性サービス・仮名サービスには非対応
  • Built for Keycloak 8.0.1 on WildFly (standalone.xml, admin theme wsfed) — not usable on current Keycloak without porting.WildFly上のKeycloak 8.0.1向け（standalone.xml、管理テーマ wsfed）。現行Keycloakでは移植しないと使えない
  • Inactive since 2020, and licensed under AGPL-3.0.2020年以降は活動停止。ライセンスはAGPL-3.0

Requirements前提条件

  • Build cloudtrust-common first, then install the module and set the wsfed admin theme.先にcloudtrust-commonをビルドしてからモジュールを導入し、管理テーマを wsfed にする
