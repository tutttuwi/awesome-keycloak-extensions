✓What it can doできること3

  • Import a complete set of authenticator configs, authentication flows and their bindings (browser, IdP first/post login, per-client overrides) in one atomic, transactional admin API call.Authenticator設定・認証フロー・バインド（ブラウザ、IdPの初回/ログイン後、クライアントごとの上書き）を、1回のアトミックでトランザクションな管理APIで一括インポート
  • Detect re-imports of an identical config by hash and reject them (HTTP 409), so it is safe to run repeatedly from CI/CD; force=true re-applies bindings.同じ設定の再インポートをハッシュで検出して拒否（HTTP 409）するので、CI/CDから繰り返し実行しても安全。force=true ならバインドだけ再適用
  • Includes an example config-as-code toolchain (flow builder, validator, update script).config-as-codeの例（フロー生成、バリデータ、更新スクリプト）が付属

✕What it cannot do / limitsできないこと・制約2

  • Only covers authentication flows, configs and bindings — not other realm configuration.対象は認証フロー・設定・バインドだけで、それ以外のrealm設定は扱わない
  • Flow aliases get a hash prefix, so imported flow names differ from the names in your payload.フローのエイリアスにはハッシュが付くため、インポート後のフロー名はペイロードに書いた名前とは変わる

Requirements前提条件

  • JDK 21 and Maven to build; copy the JAR to providers/ and run kc.sh build; callers need manage-realm.ビルドにJDK 21とMaven。JARを providers/ に置いて kc.sh build。呼び出し側には manage-realm 権限が必要
