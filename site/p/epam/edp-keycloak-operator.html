✓What it can doできること4

  • Configure existing Keycloak instances from Kubernetes or OpenShift with custom resources (Keycloak connection, realms, groups, clients, realm users and more).KubernetesやOpenShiftから、カスタムリソース（Keycloak接続、realm、グループ、クライアント、realmユーザーなど）で既存のKeycloakを設定できる
  • Reconcile resources continuously, with cluster-scoped variants (ClusterKeycloak, ClusterKeycloakRealm).状態を継続的にリコンサイルし、クラスタスコープのリソース（ClusterKeycloak、ClusterKeycloakRealm）も使える
  • Keep resources in Keycloak when the CR is deleted (edp.epam.com/preserve-resources-on-deletion annotation).CRを削除してもKeycloak側のリソースを残せる（edp.epam.com/preserve-resources-on-deletion アノテーション）
  • Install via Helm; its Go Admin REST API client can also be used as a standalone library.Helmでインストールできる。内蔵のGo製Admin REST APIクライアントは単体のライブラリとしても使える

✕What it cannot do / limitsできないこと・制約4

  • Does not install or run Keycloak itself — it only configures an existing instance.Keycloak自体のインストールや運用はしない。既存インスタンスを設定するだけ
  • Supports Keycloak 26.4 to 26.8 only.対応はKeycloak 26.4〜26.8のみ
  • Resources must be deleted in order (realm resources, then realms, then the Keycloak CR) or they can get stuck.リソースは順番に削除しないと（realm内リソース → realm → Keycloak CR）削除処理が止まることがある
  • The operator user only has realm-management roles on realms it created; other realms need extra roles.オペレーター用ユーザーが管理ロールを持つのは自分で作成したrealmだけ。それ以外のrealmには追加のロールが必要

Requirements前提条件

  • Kubernetes 1.32+ or OpenShift 4.19+, Helm 3, cluster-admin access, and cert-manager (unless webhooks are disabled).Kubernetes 1.32以上かOpenShift 4.19以上、Helm 3、クラスタ管理者権限、cert-manager（Webhookを無効にする場合は不要）
  • A Keycloak master-realm user with create-realm, stored in a Kubernetes secret.create-realm ロールを持つmaster realmのユーザーを、KubernetesのSecretに登録
