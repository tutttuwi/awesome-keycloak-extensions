✓What it can doできること4

  • Add CAS as a client protocol, so CAS applications can log in through Keycloak.クライアントプロトコルとしてCASを追加し、CAS対応アプリがKeycloakでログインできる
  • CAS 1.0/2.0/3.0 compliant login, logout and service-ticket validation, including Single Logout.CAS 1.0/2.0/3.0準拠のログイン・ログアウト・サービスチケット検証。シングルログアウトにも対応
  • Check the service parameter against the client's redirect URIs; respond in JSON or XML.service パラメータをクライアントのリダイレクトURIと照合。応答形式はJSONとXML
  • Map custom user attributes to CAS assertion attributes.任意のユーザー属性をCASのアサーション属性にマッピング

✕What it cannot do / limitsできないこと・制約4

  • SAML request/response (an optional part of CAS 3.0) is not implemented.SAMLのリクエスト/レスポンス（CAS 3.0のオプション機能）は未実装
  • Long-term tickets / remember-me are out of scope.長期チケット（Remember-Me）は対象外
  • CAS carries no client ID, so clients are identified only by their redirect URIs.CASにはクライアントIDがないため、クライアントはリダイレクトURIだけで識別される
  • Some SPs need separate login/validate URLs (/login, /serviceValidate) instead of the CAS base URL.SPによってはCASのベースURLではなく、ログインURL（/login）と検証URL（/serviceValidate）を個別に指定する必要がある

Requirements前提条件

  • Use the plugin version that matches your Keycloak version and update it with every Keycloak upgrade.Keycloakと同じバージョンのプラグインを使い、Keycloakを更新するたびに入れ替える
  • Copy the JAR into providers/ and run kc.sh build.JARを providers/ に置いて kc.sh build を実行
