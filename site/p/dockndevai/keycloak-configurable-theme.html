✓What it can doできること4

  • Use one theme for every realm and drive layout, colours, logo, favicon, fonts, texts, banner and footer from configuration instead of separate theme folders.1つのテーマを全realmで使い、レイアウト・色・ロゴ・ファビコン・フォント・文言・バナー・フッターを、テーマフォルダを分けずに設定だけで切り替えられる
  • Brand the login page, account and admin consoles and emails, in light and dark mode.ログイン画面・アカウント/管理コンソール・メールをブランディングでき、ライト/ダークの両モードに対応
  • Layer settings: built-in defaults → branding.json (global and per realm) → realm overrides through a REST API or an admin "Branding" tab; file changes reload without restart.設定は、組み込みの既定値 → branding.json（全体とrealm別）→ REST APIや管理画面の「Branding」タブでのrealm別上書き、の順に重なる。ファイルの変更は再起動なしで反映
  • Built-in layouts (centered, split-left/right, minimal) plus custom CSS layouts added without a rebuild.組み込みのレイアウト（中央、左右分割、ミニマル）に加え、独自CSSのレイアウトも再ビルドなしで追加できる

✕What it cannot do / limitsできないこと・制約4

  • Uses internal Keycloak SPIs for login, email and REST — re-test on every Keycloak upgrade (a warning is logged).ログイン・メール・RESTにKeycloakの内部SPIを使うため、Keycloakを更新するたびに再テストが必要（起動時に警告が出る）
  • The admin-console Branding tab needs the experimental declarative-ui feature; without it, use the REST API.管理コンソールのBrandingタブには実験的な declarative-ui 機能が必要。なければREST APIを使う
  • Built and tested against Keycloak 26.8.0 only.ビルド・テストはKeycloak 26.8.0のみ
  • Customisation is limited to configuration and layout CSS — not a full template rewrite.カスタマイズは設定とレイアウトCSSの範囲内で、テンプレートを丸ごと書き換えるものではない

Requirements前提条件

  • Java 21; put the JAR in /opt/keycloak/providers/ (or use the Docker image), then kc.sh build.Java 21。JARを /opt/keycloak/providers/ に置き（またはDockerイメージを使い）、kc.sh build
