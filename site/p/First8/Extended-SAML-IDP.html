✓What it can doできること3

  • Add a SAML identity provider that can send direct (synchronous, artifact) SAML requests to external providers such as eHerkenning or DigiD, which stock Keycloak does not support.標準のKeycloakが対応していない、直接（同期・Artifact）のSAMLリクエストを外部IdP（eHerkenning、DigiDなど）に送れるSAML IdPを追加
  • Support encrypted SAML attributes (used by eHerkenning).暗号化されたSAML属性に対応（eHerkenningで使われる）
  • Ships a custom frontend and theme to manage the provider's specialised settings through the REST API.プロバイダーの特殊な設定をREST API経由で管理するための、独自フロントエンドとテーマが付属

✕What it cannot do / limitsできないこと・制約2

  • On Keycloak 21+ some specialised settings are hidden in the Admin Console (legacy UI removed) — use the REST API or the bundled frontend.Keycloak 21以降は管理コンソールで一部の特殊な設定が表示されない（旧UIが廃止されたため）。REST APIか付属のフロントエンドを使う
  • Each Keycloak minor needs a manual upgrade by patching copied Keycloak classes, so new Keycloak versions lag behind.Keycloakのマイナーバージョンごとに、コピーしたKeycloakのクラスへ手作業でパッチを当てて追従する必要があり、新バージョンへの対応は遅れがち

Requirements前提条件

  • The JAR in providers (Quarkus), and a saml-extended client in the master realm for the frontend.JARを providers に配置（Quarkus版）。フロントエンド用にmaster realmの saml-extended クライアントも必要
