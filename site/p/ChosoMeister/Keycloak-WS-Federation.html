✓What it can doできること5

  • Run Keycloak as a WS-Federation 1.2 (passive) IdP/STS for relying parties, with sign-in, sign-out and metadata.KeycloakをWS-Federation 1.2（パッシブ）のIdP/STSとして動かせる。サインイン・サインアウト・メタデータ生成に対応
  • Broker to an external WS-Federation IdP, with attribute-to-user and attribute-to-role mappers.外部のWS-Federation IdPとブローカー連携でき、属性をユーザーやロールにマッピングするマッパーもある
  • Issue SAML 2.0 or legacy SAML 1.1 assertions, with user attribute/property, group and role mappers.SAML 2.0と旧SAML 1.1のアサーションを発行でき、ユーザー属性・プロパティ・グループ・ロールのマッパーに対応
  • Optionally enable WS-Trust 1.3 usernamemixed and mex endpoints per realm.realmごとに、WS-Trust 1.3の usernamemixed と mex エンドポイントを有効にできる
  • A maintained rework of the old WildFly-era extension for Quarkus-based Keycloak, with a demo stack and production runbook.WildFly時代の旧拡張を、Quarkus版Keycloak向けに作り直してメンテナンスしているもの。デモ環境と本番導入の手順書付き

✕What it cannot do / limitsできないこと・制約4

  • Supports Keycloak 26.7.x only — its minor version must match Keycloak's, because it uses internal SPIs.対応はKeycloak 26.7.xのみ。内部SPIを使うため、マイナーバージョンをKeycloakと一致させる必要がある
  • Other WS-Trust profiles (Windows or certificate authentication), and attribute and pseudonym services, are out of scope.他のWS-Trustプロファイル（Windows認証・証明書認証）や、属性サービス・仮名サービスは対象外
  • Interoperability with every AD FS / third-party WS-Fed implementation is not guaranteed.すべてのAD FSやサードパーティのWS-Fed実装との相互運用性は保証されていない
  • Some security corrections (e.g. a mandatory audience check) can break deployments that relied on the old behaviour and cannot be turned off; licensed under AGPL-3.0.一部のセキュリティ修正（audienceチェックの必須化など）は旧来の挙動に頼っていた環境を壊す可能性があり、無効化もできない。ライセンスはAGPL-3.0

Requirements前提条件

  • JDK 21 and Maven 3.9+ to build; copy the JAR into providers and run kc.sh build (recreate containers to pick up a new version).ビルドにJDK 21とMaven 3.9以上。JARを providers に置いて kc.sh build（新しいバージョンを反映するにはコンテナを作り直す）
